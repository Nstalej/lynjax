## v0.6 locked scope

### Must fix for v0.6

1. Frontend submits at least one safe demo assessment to the backend.
2. Backend response contains stable structured fields for ID, targets, checks, evidence summary, timestamp, and status/risk.
3. Frontend renders returned data and clearly labels the workflow as local/demo/sanitized.
4. Markdown report is generated from the actual backend response, not static-only template text.
5. Validation commands pass in the available environment:
   - `python -m pytest backend/tests -v`
   - `npm --prefix frontend run build`
   - `bash scripts/lab_validate.sh`

### Defer to v0.7

- Local persistence of assessment executions/evidence in JSON or SQLite.
- Evidence purge/sanitization UX.
- History view for prior runs.
- More complete report archive management.

### Defer to v0.8 or later

- Controlled field-beta checklist enforcement.
- Safe checks against explicitly authorized real targets.
- Credential handling or vault integration.
- SNMP/SSH/device integrations.
- GNS3/EVE-NG implementation.

### Needs Alejandro decision

- Whether Day 5 should publish `v0.6-rc1` for testing or `v0.6` final.
- Whether current brand/product shell work in the pre-existing untracked plan should be merged into the v0.6 scope or kept separate.
- Whether `frontend/dist/` should remain local/generated only or become a committed artifact for specific demos.
